# v1.1.0 — Quality, Reliability & Methodology Enhancement

Branch `feature/v1.1-quality-enhancements`, based on `main` at v1.0.0 (`9c5010d`). The plan, audit and reproduced defects are in [`V1.1_IMPLEMENTATION_PLAN.md`](V1.1_IMPLEMENTATION_PLAN.md); test results are in [`TESTING.md`](TESTING.md).

## P0 — Save reliability

- **Save queue** (`src/lib/saveQueue.ts`):
  - writes start on every edit, one at a time, and only the latest snapshot is written next;
  - failed snapshots are kept and retried after 1, 3, 10 and 30 s, then marked *Retry required*;
  - an older snapshot never overwrites a newer one;
  - `flush()` waits for every pending write and returns `{ ok, unsaved, error }`;
  - deleting a project waits for an in-flight write.
- **Explicit states** in the header: *Saving… (n unsaved)*, *Unsaved changes*, *Saved — all changes stored on this device*, *Save failed — retrying* and *Retry required*. *Saved* appears only after storage confirms the write.
- **Recovery journal** (`src/lib/journal.ts`):
  - a synchronous `localStorage` copy is taken when a write fails, and when the tab is hidden, closed or reloaded with pending changes;
  - on start-up, copies newer than storage (or equally recent but different) are restored, saved again and named in a notice. Stale copies are removed;
  - fixes **D7**: a change made while storage was failing was lost on reload.
- **Lifecycle** (`src/lib/lifecycle.ts`): on hidden, the app takes a copy and flushes; on `pagehide`, a copy and a best-effort flush; on `beforeunload`, a copy and a confirmation, only when changes are unsaved. Asynchronous writes started while the page closes are **not** claimed to complete.
- **Banner**: *Retry now*, *Export backup*, and whether the recovery copy could be stored. Imports and the sample project report storage failures instead of claiming success.

## Data-loss protection (backups)

- A **Backup and storage** panel on the dashboard (`src/lib/backup.ts`):
  - the last backup date and the projects with changes not in any backup;
  - whether the browser protects the storage from being cleared, with a button to ask for protection.
- **Share backup** (Web Share API) sends the file to Google Drive, WhatsApp, email and so on, where the phone supports it. *Download backup* works everywhere. If sharing fails, the file is downloaded instead.
- A **reminder** appears after a week of changes outside any backup; *Later* hides it for three days.
- Backup times are kept in `localStorage` (`psl.backups`), separate from project data. Every export (all projects, one project, report) is recorded; imported projects count as backed up.

## P1 — Evidence-based findings and recommendations

- **Finding classes** (`src/lib/evidence.ts`): *verified*, *partially supported*, *preliminary*, *inconclusive* and *unsupported claim*.
  - Each class is shown with its reasons.
  - A linked analysis alone is not verification.
  - Assumptions and interpretations never count as strong evidence.
- **Evidence-quality panel** per finding: reliability, accuracy, completeness, recency and confidence; and whether analyses document their limitations.
- **Recommendation states**: *evidence-backed*, *partially supported*, *precautionary* (explicitly marked and justified), *requires further investigation* and *unsupported*. Each comes with its reason, the issues addressed and the limitations affecting it.
- **Step states**: *Complete*, *Complete with documented limitations*, *Needs further evidence*, *Incomplete*, with a quality-check list. Documented uncertainty is accepted; unsupported claims are not.

## P2 — Structure review

- The guided review has six questions (two new: causes vs. symptoms/consequences, and tree type). Each has an explanation and read-only observations: near-duplicates, single-child and crowded branches, mixed forms, tagged symptoms/consequences, untagged branches, and mismatches with the tree type.
- **Review record**: overlaps, missing areas, corrections, reviewer and comments, included in the report.
- **Branch roles**: driver/component, root cause, contributing factor, symptom, consequence.
- **Issue tree vs. hypothesis tree** comparison.
- Acceptance stays a human judgement and is flagged again when the tree changes.

## P3 — Synthesis

- A **data → finding → insight → implication → so what? → decision relevance** ladder with definitions, a worked example and a seven-question worksheet.
- Findings are written rung by rung, with an optional prior belief.
- A *“Because …, …”* one-sentence draft built only from the user's own words.
- Warnings for multi-sentence synthesis, a missing implication, an unlinked finding, or an insight that restates the finding.

## Report

Thirteen sections in English or Arabic, including:
- an evidence register grouped by class, with a legend;
- verified conclusions separated from other findings;
- implications;
- a reasoning chain for every recommendation (state, findings, issues, limitations);
- an implementation plan with status;
- risks and outstanding questions, with open quality checks.

## UX

Labels separate data entry, automatic validation, methodological review and completion status on every step.

## Data model

Schema v2 (unreleased before this version, so no v3 is needed):
- `IssueNode.kind`;
- `Recommendation.precautionary` and `precautionaryJustification`;
- two review questions;
- `StructureStep.review`;
- `Finding.decision` and `priorBelief`.

Stored projects and backups are migrated automatically from v1. See [`DATA_MODEL.md`](DATA_MODEL.md).

## CI

On every pull request and push: lint (oxlint), type-check, unit tests and the production build, then Playwright acceptance tests. Deployment runs only from `main` after both pass. Failure artifacts are kept for 14 days.

## Known limitations

See [`TESTING.md` → Known limitations](TESTING.md#known-limitations). In short:
- asynchronous writes started while the page closes may be aborted (the recovery copy covers this);
- the recovery copy is limited by `localStorage` quota;
- observations and hints are heuristics;
- oxlint is used instead of ESLint;
- the Pages deploy actions still raise the Node 20 notice;
- there is no sync.
